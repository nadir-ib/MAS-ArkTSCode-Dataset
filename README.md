# MAS-ArkTSCode Dataset

6,034 prompt–code pairs for **ArkTS** (the HarmonyOS application language), generated by the
MAS-ArkTSCode multi-agent framework and verified with the official ArkTS compiler. Every record carries
the original prompt, the enhanced prompt when prompt enhancement was used, the final generated code,
the compiler verdict, an automated quality score (1–10) and basic code metrics.

The dataset accompanies the paper

> İbrahimoğlu, N., Demirezen, M.U.: *Compiler-Validated Code Generation for ArkTS on HarmonyOS: A Multi-Agent Framework and a Controlled Decomposition of Its Mechanisms*. Automated Software Engineering (Springer), accepted 2026.

## Quick start

```python
import pandas as pd

df = pd.read_csv("mas_arkts_dataset.csv")

print(len(df))                                    # 6034
print(df["compilation_success"].mean())           # 0.8861
print(df["high_quality_success"].mean())          # 0.8613
compiled = df[df["compilation_success"]]
print(compiled["quality_score"].agg(["mean", "std"]))   # 7.86, 0.95

# distinct prompts only (drops the 60 repeated records, see "Composition")
distinct = df.drop_duplicates(subset="prompt")
```

Run `python3 scripts/verify_statistics.py` to recompute and check all numbers below.

## Composition: repeated prompts and repeated code

**Repeated prompts.** The file contains 6,034 records covering 5,974 distinct prompts. 60 prompts
appear twice, and the two records of such a prompt are identical in every field (exact-duplicate rate
1.0 %). Computing the headline rates over distinct prompts instead of records changes them by less than
0.1 percentage point (88.57 % compilation and 86.06 % high-quality, against 88.61 % and 86.13 %).

**Repeated code.** The prompt pool contains many paraphrases of the same task (for example several
wordings of "a three-tab bottom navigation"). With low-temperature decoding, paraphrased prompts often
received byte-identical code. Measured on `final_code`:

| Quantity | Value |
|---|---|
| Distinct `final_code` strings | 5,405 of 6,034 |
| Records whose code is identical to at least one other record | 873 (14.5 %); 865 of them compiled |
| Identical-code clusters | 244 (165 of size 2; largest clusters 87 and 50 records) |
| Records in at least one near-duplicate pair (Jaccard ≥ 0.80 on 5-token shingles) | 1,851 (30.7 %) |

Prompts inside an identical-code cluster are paraphrases of each other (mean token Jaccard 0.52,
against 0.13 for random prompt pairs). No deduplication was applied to the released file; it is the
complete set of workflow records. Users who need unique code should deduplicate on `final_code`, or use
`coverage/near_duplicate_pairs.csv`, which lists every pair at or above the 0.80 threshold. Threshold
sweeps (0.5–1.0) are in `coverage/coverage_summary.json`. None of the compilation or quality statistics
in the paper were computed after deduplication; they describe the records as generated.

## Fields

| Field | Type | Description |
|---|---|---|
| `sample_id` | int | 1 … 6034 |
| `prompt` | str | natural-language task description given to the system |
| `enhanced_prompt` | str or empty | prompt rewritten by the Prompt Enhancer agent; present for 1,043 records |
| `final_code` | str | final ArkTS source produced by the workflow (for failed records: the last attempt) |
| `compilation_success` | bool | final code compiled with the HarmonyOS SDK 5.0.0.71 (API 12) ArkTS compiler |
| `high_quality_success` | bool | `compilation_success` and `quality_score ≥ 7` |
| `technical_success` | bool | `compilation_success` and `quality_score < 7` |
| `quality_score` | float | Quality Scorer agent score, 1–10; 0 for records that never compiled |
| `iteration_count` | int | number of agent iterations recorded for the workflow |
| `enhancement_attempted` | bool | prompt enhancement was triggered (1,243 records) |
| `code_length` | int | `len(final_code)` |
| `line_count` | int | number of lines of `final_code` |
| `component_count` | int | occurrences of `@Component` |
| `state_count` | int | occurrences of `@State` |
| `import_count` | int | import statements recorded by the workflow |

Notes. `enhancement_attempted` is true for 1,243 records but `enhanced_prompt` is stored for 1,043;
for the remaining 200 the enhancement step ran without a stored rewritten prompt. `import_count`
differs from a line-anchored regex count in 6 records (0.1 %). The 687 failed records keep the last
code attempt as produced; 26 of them contain model output that is not code (markdown fences or
leaked tool-call text). All 26 are compilation failures with score 0, so they do not affect any success
statistic. The CSV contains no error messages; compiler diagnostics were not exported.

## Coverage tables (`coverage/`)

Generated from the CSV by `scripts/compute_coverage.py` using lexical (regular-expression) extraction;
the exact patterns are listed in `coverage/extractor_schema.json`. Every table reports total occurrences,
the number and share of records with at least one occurrence, and the same count over compiled records.

| File | Content |
|---|---|
| `decorators.csv` | ArkUI/ArkTS decorators (`@Entry` 99.9 %, `@Component` 99.9 %, `@State` 91.0 %, `@Builder` 20.1 %, `@Prop` 1.0 %, …) |
| `lifecycle_handlers.csv` | `aboutToAppear` 7.1 %, `aboutToDisappear` 2.3 %, `onPageShow`, `onPageHide`, … |
| `import_modules.csv`, `import_families.csv`, `import_cooccurrence_top15.csv` | imported `@ohos.*` / `@kit.*` modules (1,191 records import at least one module), per-namespace families, co-occurrence of the 15 most frequent modules |
| `arkui_components.csv` | built-in ArkUI components (`Column` 98.5 %, `Text` 89.4 %, `Button` 65.2 %, `Image` 52.1 %, `ForEach` 46.6 %, `List` 20.9 %, …) |
| `control_flow_and_typing.csv` | conditionals, loops, `async`/`await`, `Promise`, generics, type annotations, classes, interfaces, … |
| `ui_patterns.csv` | list views, navigation, tabs, forms, dialogs, state-management patterns, animation, gestures, … |
| `size_complexity_per_sample.csv`, `size_complexity_summary.csv` | characters, lines, comment lines, methods, arrow functions, structs, custom-component instantiations, maximum brace nesting |
| `near_duplicate_pairs.csv` | all record pairs with Jaccard ≥ 0.80 |
| `coverage_summary.json` | consistency checks, deduplication metrics with threshold sweep, and the top rows of every table |

## Quality assessment

Scores were produced by the Quality Scorer agent (DeepSeek V3) on four criteria: import correctness,
syntax correctness, logic correctness, readability and maintainability. The full scoring prompt and the
threshold are in `REPRODUCIBILITY.md`. The scorer was validated against two HarmonyOS developers on a
stratified sample of 150 compiled records: Pearson r = 0.84, Spearman ρ = 0.82, ICC(2,1) = 0.81. The
human study validates the ranking produced by the scorer, not the absolute 86.1 % high-quality rate.

## Intended use and limitations

Intended for research on code generation for low-resource languages, for retrieval corpora, fine-tuning
and evaluation of ArkTS models, and for teaching. The code is synthetic, was generated with the
HarmonyOS SDK 5.0.0.71 (API 12) and is not reviewed for production use. Compilation success means the
code compiled; it does not establish functional correctness against the prompt. The quality score is a
model judgement. Paraphrased prompts and repeated code (see Composition) should be handled before
training or evaluation. See `DATASHEET.md` for the full discussion.
