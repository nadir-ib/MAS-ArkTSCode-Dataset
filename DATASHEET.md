# Datasheet for the MAS-ArkTSCode Dataset

Following Gebru et al., "Datasheets for Datasets", Communications of the ACM 64(12), 2021.

## Motivation

**Why was the dataset created?** ArkTS, the application language of HarmonyOS, has very little public
training and evaluation data. The dataset was created to study whether a coordinated multi-agent
generation pipeline with a compiler in the loop can produce compiler-verified ArkTS code at scale, and to
release the resulting prompt–code pairs for research.

**Who created it and who funded it?** Nadir İbrahimoğlu and Mustafa Umut Demirezen, in the course of the
research reported in the accompanying paper (Automated Software Engineering, Springer, 2026, https://doi.org/10.1007/s10515-026-00695-w). No external
funding is declared.

## Composition

**What do the instances represent?** Each row is one workflow execution: a natural-language prompt
describing a HarmonyOS/ArkUI application or component, the final ArkTS source produced for it, the
compiler verdict, an automated quality score and basic code metrics. 15 fields; see `README.md`.

**How many instances?** 6,034 records over 5,974 distinct prompts. 60 prompts appear twice with
identical records.

**Is it a sample or the complete set?** The complete set of workflow records produced in the experiment.
No records were removed, and no deduplication was applied.

**Are there recommended splits?** No. Users who build train/test splits should split by `final_code`
cluster or by near-duplicate group (`coverage/near_duplicate_pairs.csv`), because the prompt pool
contains paraphrases of the same task and 873 records share byte-identical code with another record.

**Errors, noise, redundancies.** 687 records (11.4 %) did not compile; their `final_code` is the last
attempt and 26 of them contain non-code model output (markdown fences or leaked tool-call text), all with
`quality_score = 0`. Quality scores are model judgements validated for rank order against two human raters
(r = 0.84, ρ = 0.82, ICC = 0.81) but not for absolute level; the automated scores run about 0.7 points
higher than the human scores. `import_count` disagrees with a simple regex count in 6 records.

**Does it contain confidential data, offensive content or personal data?** No. Prompts describe UI and
application tasks; code uses placeholder resources. The file was scanned for API keys, local paths,
hostnames and e-mail addresses; none are present. No people are identified.

## Collection process

**How was the data acquired?** Generated by the MAS-ArkTSCode framework: for each prompt, retrieval of
similar ArkTS examples, generation by DeepSeek V3, compilation with the HarmonyOS SDK 5.0.0.71 (API 12)
ArkTS compiler, up to 10 compiler-guided correction attempts, automated scoring, and up to 2 prompt
enhancement passes. Every state transition was persisted to a MongoDB store, from which the CSV was
exported on 2025-09-15. Configuration details are in `REPRODUCIBILITY.md`.

**Where do the prompts come from?** The prompt pool consists of natural-language task descriptions for
HarmonyOS applications and components, written in English, and includes paraphrased variants of the
same task. Prompts are stored verbatim in the `prompt` field.

**Who was involved?** The authors ran the generation; two HarmonyOS developers took part in the human
validation of the scorer (150 records). No crowdworkers.

**Over what time frame?** Generation runs took place in 2025; the release file was exported on
2025-09-15.

## Preprocessing, cleaning, labelling

The `final_code` field is the code as produced by the workflow; ANSI codes and surrounding model text
were not stripped (hence the 26 non-code failures). Labels (`compilation_success`, `quality_score` and
the derived booleans) were produced by the compiler and the Quality Scorer agent, not by humans. Code
metrics were computed by the export script. The raw workflow database is not public.

## Uses

**What has the dataset been used for?** The intrinsic evaluation in the accompanying paper, including a
500-prompt stratified subset used for baseline comparisons.

**What could it be used for?** Retrieval corpora for ArkTS code assistants; fine-tuning and evaluating
code models on a low-resource language; studying compiler-guided repair; teaching ArkUI patterns.

**What should it not be used for?** Production deployment without review; as evidence of functional
correctness (compilation does not test behaviour); as a benchmark with the raw records as independent
test items (see the redundancy notes above).

## Distribution

Public GitHub repository https://github.com/nadir-ib/MAS-ArkTSCode-Dataset, CC BY 4.0 for the data and documentation and MIT for the scripts, from
October 2026 (version 1.1; version 1.0 was placed in the repository on 2025-09-15). No fees or
access restrictions.

Maintained by the authors (contact in `README.md`). Corrections and additions are announced in `README.md`;
the data file is versioned by its md5 in `checksums.md5`. Issues can be opened on the repository.
